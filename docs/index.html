Core Technical Reference

Architectural Implementations

Compare the mathematical foundation, DDL schemas, index configurations, and PostgreSQL execution plan behaviors for each model.

1. Adjacency List

sql/01_adjacency_list.sql

The canonical relational approach: each entity stores a nullable parent_id referencing the primary key of its direct parent. 

-- Schema & Traversal Index
CREATE TABLE regions (
    id SERIAL PRIMARY KEY,
    name TEXT NOT NULL,
    level TEXT NOT NULL,
    code TEXT,
    parent_id INT REFERENCES regions(id) ON DELETE CASCADE
);
CREATE INDEX idx_regions_parent_id ON regions(parent_id);

-- Subtree Fetch: Recursive CTE
WITH RECURSIVE subtree AS (
    SELECT id, name, level, parent_id
    FROM regions WHERE name = 'Nairobi'
    UNION ALL
    SELECT c.id, c.name, c.level, c.parent_id
    FROM regions c JOIN subtree s ON c.parent_id = s.id
)
SELECT * FROM subtree;
  • ⚡ O(1) Writes: 685 TPS reparenting (single-row update).
  • 📦 Zero Bloat: 0 kB auxiliary table footprint.
  • 🔍 Buffers: 317 shared hits during 131-node recursive CTE scan.

2. Nested Sets

sql/02_nested_sets.sql

Represents nodes as nested intervals (lft, rgt) assigned via depth-first search traversal, turning subtree reads into pure index range scans. 

-- Bounds & Composite Index
ALTER TABLE regions ADD COLUMN lft INT;
ALTER TABLE regions ADD COLUMN rgt INT;
CREATE INDEX idx_regions_lft_rgt ON regions(lft, rgt);

-- Subtree Fetch: O(1) Range Scan
SELECT c.id, c.name, c.level, c.lft, c.rgt
FROM regions root
JOIN regions c ON c.lft BETWEEN root.lft AND root.rgt
WHERE root.name = 'Nairobi';
  • 🚀 Low Buffers: Only 25 shared hits (0.161 ms execution time).
  • ⚠️ Write Amplification: 1.22 TPS write collapse on reparenting.
  • 🔒 Global Locking: Interval shifts lock all 6,158 rows.

3. Closure Table

sql/03_closure_table.sql

De-normalizes the entire hierarchy graph into an auxiliary transitive table recording every ancestor-descendant pair with depth distance. 

-- Transitive Table & Indexing
CREATE TABLE region_closure (
    ancestor_id INT REFERENCES regions(id) ON DELETE CASCADE,
    descendant_id INT REFERENCES regions(id) ON DELETE CASCADE,
    depth INT NOT NULL,
    PRIMARY KEY (ancestor_id, descendant_id)
);
CREATE INDEX idx_closure_anc ON region_closure(ancestor_id, depth);

-- Subtree Fetch: Single Join
SELECT r.id, r.name, r.level, c.depth
FROM region_closure c
JOIN regions r ON r.id = c.descendant_id
WHERE c.ancestor_id = (SELECT id FROM regions WHERE name = 'Nairobi' LIMIT 1);
  • 🕸️ DAG Capable: Supports multiple parents per node.
  • 🐘 Heavy Bloat: 29,000 rows (+3.62 MB, +60% table size).
  • 📊 Buffers: 424 shared hits during subtree fetch.

4. PostgreSQL ltree

sql/04_ltree.sql

PostgreSQL native materialized label path extension with GiST index acceleration, regex-like matching, and depth functions. 

-- Enable Extension & GiST Index
CREATE EXTENSION IF NOT EXISTS ltree;
ALTER TABLE regions ADD COLUMN path LTREE NOT NULL;
CREATE INDEX idx_regions_path_gist ON regions USING GIST (path);

-- Subtree Fetch: GiST Containment (<@)
SELECT id, name, level, path
FROM regions
WHERE path <@ 'Kenya.Nairobi';

-- Ancestor Lookup: Path Containment (@>)
SELECT id, name, level, path
FROM regions
WHERE path @> 'Kenya.Nairobi.Sub_1.Ward_1.Village_1';
  • 👑 Read Champion: 4,388 TPS Subtree, 7,278 TPS Ancestor.
  • 🎯 Rich Operators: Wildcards (Kenya.*.Ward_1) and lquery.
  • ⚡ GiST Indexing: 109 buffer hits for 131 nodes (0.89 ms).

Engineering Trade-Offs

Production Decision Matrix

How to select the right hierarchical modeling architecture for your application's read/write ratio and requirements.

PostgreSQL ltree

Read-Dominant & Complex Search
  • ✓ Highest Subtree Read Throughput (4,388 TPS).
  • ✓ Highest Ancestor Lookup (7,278 TPS).
  • ✓ Native regex pattern matching & lquery syntax.
  • ✓ GiST indexing with balanced tree maintenance.
  • ✗ Requires PostgreSQL extension (proprietary).

Adjacency List

Write-Heavy & Mutable Trees
  • ✓ Highest Write Throughput (685 TPS).
  • ✓ Single-row O(1) pointer update for subtree moves.
  • ✓ Zero storage overhead (0 kB bloat).
  • ✓ 100% ANSI SQL standard compliant.
  • ✗ Slower recursive CTE reads on deep hierarchies.

Closure Table

DAGs & Multi-Parent Graphs
  • ✓ Supports Directed Acyclic Graphs (multiple parents).
  • ✓ Portable across MySQL, SQLite, Oracle, PostgreSQL.
  • ✓ Simple single-join queries without recursion.
  • ✗ Heavy storage expansion: O(N · D) rows (+60% disk).
  • ✗ Complex Cartesian joins when reparenting subtrees.

Nested Sets

Static Read-Only Taxonomies
  • ✓ Fast O(1) subtree range reads (3,672 TPS).
  • ✓ Lowest buffer hits (25 shared hits for 131 nodes).
  • ✓ Standard ANSI SQL BETWEEN operators.
  • ✗ Severe write collapse on reparenting (1.22 TPS).
  • ✗ Table-locking boundary cascades on writes.
